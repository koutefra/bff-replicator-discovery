# Replicator Discovery in BFF — interactive companion

This directory contains the static companion to *Replicator Discovery Is Faster Without Population Coupling in a Self-Modifying Program Soup*. It explains the U → R → N discovery result, the standard BFF interaction cycle, a representative reconstructed discovery event, functional pre-replicator availability and activation, and the N/R operator-frequency profiles.

The site uses plain HTML, CSS, JavaScript, SVG, MP4, and one compact JSON file. It has no runtime backend or package dependencies.

## Run locally

Requirements:

- Python 3
- a current browser

From the repository root:

    cd web-demo
    python3 -m http.server 8000

Open http://localhost:8000. HTTP serving is required because the page fetches data/research-data.json.

## Production build and validation

From the repository root:

    python3 web-demo/scripts/build_site.py
    python3 web-demo/scripts/validate_build.py web-demo/dist

Preview the exact artifact:

    python3 -m http.server 8000 --directory web-demo/dist

The build copies the HTML, CSS, JavaScript, favicon, browser data, and media into web-demo/dist, then adds .nojekyll. The validator checks required files, JSON validity, every local HTML/CSS media reference, and project-site-safe relative URLs.

## Regenerate the browser data

The committed JSON is ready to serve. To rebuild it from the repository results:

    python3 web-demo/scripts/export_data.py
    python3 web-demo/scripts/build_site.py
    python3 web-demo/scripts/validate_build.py web-demo/dist

Data regeneration uses NumPy and Matplotlib from the repository analysis environment. Serving, building, and validation use only the Python standard library.

## Refresh the explanatory videos

The tracked MP4 files are browser-friendly conversions of the repository presentation animations. To regenerate them, run from the repository root:

    cp analysis_plots/presentation/bff_soup_interaction_poster.png web-demo/assets/bff-soup-poster.png
    cp analysis_plots/presentation/selfrep_test_poster.png web-demo/assets/selfrep-test-poster.png
    env -u LD_LIBRARY_PATH ffmpeg -y -i analysis_plots/presentation/bff_soup_interaction.gif -vf "pad=ceil(iw/2)*2:ceil(ih/2)*2" -movflags +faststart -pix_fmt yuv420p web-demo/assets/bff-soup.mp4
    env -u LD_LIBRARY_PATH ffmpeg -y -i analysis_plots/presentation/selfrep_test.gif -vf "pad=ceil(iw/2)*2:ceil(ih/2)*2" -movflags +faststart -pix_fmt yuv420p web-demo/assets/selfrep-test.mp4

The original animations are generated by:

- scripts/render_bff_presentation_animation.py
- scripts/render_selfrep_test_animation.py

The self-replicator animation abbreviates the display to two example trials; the page text states the exact 13-trial test.

## Display semantics

- The browser trace is precomputed from the repository evaluator; the page is not an arbitrary BFF interpreter.
- Copy arrows are the explanatory phase paths defined by the source figure. They appear at phase milestones rather than as a per-instruction write log.
- M(t) is functional participation in formation, not raw occurrence of the five instruction values.
- Sparse R M(t) values use a centered 500-epoch mean. N M(t) is replaced by its across-time mean, matching the uniform-partner baseline treatment. Raw values remain in the JSON.
- A(t) is unsmoothed.
- Discovery values are events per eligible run per bin, not per-epoch hazards. R values are takeover-censored and exposure-normalized.
- Operator bars show percentages of all tape bytes. The page emphasizes [, <, >, comma, and the remaining six BFF operators combined.
- The displayed R operator profile uses only the pre-takeover portion of each run; eligible runs decline to 55 by epoch 16,000.
- The operator slider's epoch 1 point is the real per-run median at epoch 1, before any execution; N and R agree there because both start from the same uniform byte distribution.
- The one-in-1.5-million reference counts one exact relative ordering with neutral bytes elsewhere. It is neither a replicator probability nor a functional-interaction probability.
- N and R differ in both population coupling and partner distribution. The operator-profile explanation is plausible but has not been causally isolated.
